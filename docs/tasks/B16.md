## Done-whens, as built

1. **The pools** (`src/birth/pools.ts`). `CLASS_ROSTER` (9) and `RACE_ROSTER`
   (11) are the game's own, in class.json/p_race.json record order. A test
   pins them to the content package. There are 20 rules, `borg.class<Name>`
   and `borg.race<Name>` (punctuation dropped, e.g. `borg.raceHalfElf`),
   titled `Class: <Name>` / `Race: <Name>`, default on, requiresReload.
   `resolveBirthPair` draws the class at hash(2·lineage) and the race at
   hash(2·lineage + 1), using T09's murmur finalizer unchanged. So one counter
   carries both draws and they vary independently. An empty pool means the
   whole roster, logged. A name the live game does not define is dropped,
   logged. One decision line per birth.
2. **The wiring** (`src/class/birth.ts`, `plannedBirth`). Per page it reads
   the flags, the lineage counter and the game's `class`/`p_race` names. It
   resolves the pair ONCE per show, through the presenter's new `choose`, and
   bumps the counter after. `plugin.ts` calls it directly. The never-landed
   `borg.class` index, `activePack` and `packForClassValue` are gone.
3. **The presenter** (`src/class/warrior/presenter.ts`). `choose` outranks
   `raceName`. A Warrior goes through the unchanged warrior plan (reset, the
   buys, the draft check). Any other class goes through `suggested`:
   chooseRace + chooseClass leave the session on the game's own spread (the
   engine's `generateStats` = the C's `generate_stats`, player-birth.c:816-973).
   The presenter checks the draft names the pair, then accepts, with no buys.
   This answers #17's spike: the game's class records DO carry the signal
   (spell stat, blows breakpoint), so no class knowledge is invented. The
   human path is untouched: no flag means no `choose` call and no session call.
4. **The generic pack** (`src/class/generic.ts`). Its `planSuggested` is the
   same answer for the headless harness (`core.generateStats`).
   `packForClass(name)` in the registry returns the dedicated pack if one
   exists, otherwise the generic one. `tools/runs.mjs --class <Name>` measures
   any class.
5. **Removed**: `borg.raceRandom` (rule) and `borg.raceChoice` (setting),
   with their resolver. A stored value in either is simply no longer read.
   The warrior shortlist stays as measurement data (harness default
   Half-Troll, the bake-off). The lineage tests moved to `lineage.test.ts`.
6. **Title row**: "New Mandos character" (`TITLE_ROW_LABEL`), naming no class.
   The manifest description names the pools.
7. **Docs**: SETTINGS.md (the birth-pools section with recipes), docs/README.md
   (the table: 20 rows, pinned by docs-sync), README, AGENTS, process §2,
   the plan, CHANGELOG [CHOICE].

## Verification

- Fast loop: 630/630. The full `CI=1 pnpm verify` result is in the merge commit.
- New tests: `src/birth/pools.test.ts` (rosters vs content package, manifest
  mirror, draw determinism, coverage of all 9 x 11, independence, pool
  filtering, pin, empty fallback, unknown-name drop, log line, T09 hash
  walk, wiring pins). The presenter tests cover a Dunadan Rogue on the
  suggested spread (no buys, no reset), a drawn Warrior through the plan, no
  `choose` on the human path, and an unknown class declined. The registry
  tests cover the generic fallback. The play test "births and plays every

  decisions): the live player's class, race and planned base stats, and
  census == decisions.

  presenter without the generic path made 2 presenter tests fail. Both
  restored.

  are born Human with stats [17,16,10,10,16], [17,10,16,10,16] and
  [17,12,10,17,12] (INT and WIS on the spell stat: the game's own). The Mage
  and Priest die early. They play without spells, since `borg_play_magic` is
  unported (#50). Measuring every class is #31's job.
- Warrior unchanged: the warrior plan and the harness default are untouched.
