# B15 Unify repositories at M2 open: the warrior becomes strategy pack #1

- **Kind**: infrastructure (a restructuring, not a behaviour change)
- **Issue**: #15 · **Branch**: `task/B15-unify` · **Merge after**: B14 (M1
  closed)
- **Owns**: the class-agnostic instruments ported from neowarrior-borg
  (restart loop `src/loop/`, journal/graveyard `src/records/journal.ts`, the
  pack session driver merged into `src/play-session.ts`), strategy pack #1
  (`src/class/warrior/`, selected by the `borg.class` parameter), the pack
  registry (`src/class/`), `tools/runs.mjs`, the moved run records with
  their provenance note, and the wronged documents (AGENTS.md, README.md,
  docs/process.md section 2, SETTINGS.md, docs/README.md).
- **Scope**: the M2-opening unification the doctrine named (docs/process.md
  section 2): ONE session module (the stock driver and the pack driver over
  one loop body), ONE record writer (`better-borg/runs@1` wins; the archived
  fork's reporter shape stays only as the shape of the ported historical
  records), one suite with the sole tolerated red being the recorded seed-1
  door-close. Ported instruments keep their reviewed semantics exactly -
  the loop's #29/#35 flag safety, the journal's #34 install-storage archive
  (with its known concurrent-writer limitation, neowarrior #38, deliberately
  NOT fixed here so that follow-up can land cleanly), the T09 draw, the
  presenter protocol. The engine stays pristine (fingerprint pinned in the
  task's environment).
- **Semantic choices forced by conflicts** (each flagged in the commit):
  1. ONE counting rule - the archived fork's #36 fix (count the killing
     decision) applies to the stock driver too, so a dying run from here on
     records one more decision than B02's committed record did (seed 7:
     1228 recorded then, 1229 now); survivor runs and every census number
     are unchanged, and the driver now throws on any census/count
     disagreement.
  2. `borg.class` ships as the `borg.raceChoice` convention (a persisted
     numeric index over the ordered pack list), read at each page and
     honored by the wiring now; its MANIFEST ROW lands with the second pack,
     because the host's setting schema requires `min < max` strictly and a
     warrior-only 0-0 row is not a manifest the SDK validates.
  3. The moved `2026-11-02-import` record needed a name (`-neowarrior`
     suffix) because this repository already carries its own import baseline
     under that name.
  4. Core instruments get the class-agnostic renames (`installBorgRestart`,
     `installBorgJournal`, `playPackSession`, `setBirthFlag`...) with their
     log nouns made generic; the storage key `warriorBirth` is unchanged.
  5. `tools/bakeoff.mjs` does not port: its writer half is the retired
     schema; the game-free grid/guard/median module (`src/measure/bakeoff.ts`)
     does, and a future bake-off runs through the unified instrument.
- **Done when**:
  1. `pnpm vitest run --exclude 'src/play.test.ts'` is green, and
     `pnpm vitest run src/play.test.ts` shows exactly one failure - the
     recorded seed-1 door-close (close 771/1500, upstream neo-angband#428).
  2. `pnpm verify` passes (typecheck, suite, plugin.js current, grants).
  3. The engine fingerprint at head equals the one the task started from
     (`c89b1b08474b1692b352f8d0b64823f4`,
     `node_modules/@rpgm-tools/neo-angband-core/dist/game/trap.js`).
  4. The three moved record directories are byte-identical to their source
     (md5), named in docs/runs/README.md's Provenance table with the source
     repo and SHAs.
- **Hazards**: silent redesign of reviewed instruments (guarded by porting
  with fidelity and listing every rename); the historical records being
  rewritten (guarded by md5 checks); the stock driver's pinned measurements
  moving (guarded by the b15-verify sweep reproducing B02's record).
