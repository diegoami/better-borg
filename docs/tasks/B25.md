# B25 Stage-grind: retire-on-attainment saves and reach-rate as the number

- **Kind**: choice (new fork behaviour; nothing in 4.2.6 retires into a kept
  save) plus the measurement instrument that owns its number
- **Issue**: #25 · **Branch**: `task/B25-stage-grind` · **Merge after**: #19
  (the Mandos rename - slot names ship under the final id)
- **Owns**: the stage predicate and its two settings (`src/loop/stage.ts`),
  the retire protocol and the loop's retire entry (`src/loop/restart.ts`), the
  stage watch in the tick (`src/api2/controller.ts`) and its wiring
  (`plugin.ts`), the roster/session model in the harness fake
  (`src/harness-api2.ts`), the stage in both session drivers
  (`src/play-session.ts`), the stage fields and the reach-rate in the ONE
  record writer (`src/run-record.ts`), the `--stage` pass-through
  (`tools/runs.mjs`, `tools/sweep.mjs`), the manifest rows and the
  `session:control` grant, the baseline record
  (`docs/runs/2026-11-03-stage-baseline/`), and the wronged documents
  (SETTINGS.md, docs/README.md, docs/runs/README.md, AGENTS.md, CHANGELOG.md,
  docs/tasks/README.md).
- **Scope**: the purpose redirect's first rail (issue #25): a persisted stage
  definition (`borg.stageClvl` x `borg.stageDepth`, next-birth semantics like
  `borg.class`), retire-on-attainment in the restart loop (save -> rename the
  slot into the library -> create the next character, one kept save per
  successful run), reach-rate as the project's number (per-seed attained y/n
  over the standard seed grid, an additive `stageAttained`/`retired` field pair
  in `better-borg/runs@1`), and the baseline record that calibrates the
  default. ZERO engine changes; the death path is unchanged; the fail-safe
  rule is absolute - a refused save or rename logs and the run KEEPS PLAYING.
- **Semantic choices forced by the host and the measurement** (each flagged in
  the commits):
  1. The slot NAME cannot carry the owner's full "Mandos <stage> CLVL<n>
     seed<n> <date>" shape: the host's rename seam accepts 1-15 characters
     (neo-angband's `acceptedCharacterName`, charsheet.ts:250). The name is
     `M s<seed> <stage>` from the harness (the ladder's per-seed key), `M
     n<lineage> <stage>` from the mod (a mod cannot know the game seed; the
     install slot's lineage counter is the knowable per-character identity),
     truncated deterministically at 15. The date is not lost: the roster's own
     lastPlayed column shows it, and the record carries `recorded`.
  2. The slot to rename is FOUND, not guessed: after our own `session.save()`
     answers ok, the retire lists the roster and takes the alive entry whose
     level and depth match the live facts and whose lastPlayed is greatest -
     the host stamps the just-saved slot newest (saves-facade.ts). No match is
     a refused rename (fail-safe).
  3. The default stage ships at the measured frontier (clvl 2, depth 1), not
     the owner's ~clvl 20 destination: today's borg dies on depth 1 at clvl
     1-2 on the whole standard grid, so a c20 rung measures 0% everywhere and
     the data cannot choose between depths. The baseline
     (`docs/runs/2026-11-03-stage-baseline/`) brackets the frontier
     (c1d1 100%, c2d1 50%, c2d2 0% on the standard grid) and the default is
     the strongest rung inside it. The owner moves the settings as the
     strength work lands; the destination is documented in SETTINGS.md.
  4. Attainment is observed from sticky facts (`maxDepth` - the same
     first-arrival fact the journal records - and `level`), once per decision
     from the world snapshot the tick already reads: no extra host calls, no
     journal read per decision, deterministic. A stage change applies to the
     NEXT birth (rule 5), read once per page.
  5. A retired run has no run report, so it writes no graveyard entry: the
     library slot IS its record (graveyard for failures, library for
     successes). The driver records the same split (`dead`/`retired` are
     disjoint ends) and the #36 counting rule holds on the retiring decision -
     attainment is observed after the decision completes, exactly as death is.

- **Hazards**: a refused retire becoming a death loop (guarded by the
  fail-safe and its tests); the 15-character rename limit silently refusing
  every retire (guarded by the name builder's truncation and a length test);
  the retire path duplicating the protocol between the mod and the harness
  (guarded by ONE protocol function both call); historical records being
  rewritten (guarded: only additive fields, the schema id frozen, readers
  tolerate absence).
