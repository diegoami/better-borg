# B76 Recharge continuation survives speculative API2 rewind

Kind: DEFECT in our own B50 command-sequence implementation, reported on
#76 by the owner-requested documentation review (#74). Branch
`task/B76-recharge-rewind`, based on B50 main `3d4ba3d`.

The API2 tick can settle loadout questions and ask the decision again
before submitting a command. B50's new pending R75 flag was not in the
controller's pre-decision snapshot. A speculative wear therefore became
rest before the wear was submitted; a speculative rest could become a
second wear. Rewind now restores the entry value in both directions.
