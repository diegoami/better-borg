# B87 Restore west-side lantern coverage

Issue #87; kind: CHOICE correcting an inherited C defect (rule 3).
This is bug work under rule 15, not a strategy change.

## Provenance and reproduction

Credit: the owner's [borg-rs C bug catalogue, entry 4](https://github.com/diegoami/borg-rs/blob/613227bc53c4f0e77ec457d5721febe9cf8bfe03/docs/c-bugs.md#4-west-of-the-player-lights-the-wrong-grids),
tracked for future reference in #86.

`borg_update_light` in C `borg-cave-light.c:137-141` uses offsets
`(y +/- 2, x - 2)` for the west arm, where the east arm uses
`(y +/- 1, x + 2)`. It misses both west shoulder grids and appends corner
grids again. The bug exists in our 4.2.6 reference and current C master
`e473720ed88a0f0c7ca66815cef3000eb4a38bc3`, which is also borg-rs's C pin.
Our import boundary `70145c5` and the pristine TypeScript port preserve it.
Mandos stores light flags in a grid rather than C's list, so duplicated
list entries are not a separate problem here.

Before the correction, three normal-perception scenarios fail at radii
2, 3 and 5: both west shoulders are unlit in an open room, unlike their
east counterparts. The wall-gating scenario already passes. These are
geometric perception checks, not a claimed live death reproduction.

## Correction and scope

Change only the two west offsets to +/-1, preserving the existing floor
gate and other light shapes. The function's former "verbatim" description
is corrected and the departure is FORK-marked with Rust-project credit.
The plugin is rebuilt from source.

Because the C is wrong too, this does not qualify as a mod-port parity PR.
The matching C report is prepared separately under process section 6.
Nothing is changed in borg-rs, which deliberately retains C bugs for parity.

## Validation

- Before: three new shoulder/reflection scenarios fail; wall gate passes.
- After: lighting, Necromancer-light and perception suites pass (27 tests).
- `pnpm typecheck`, build and plugin currency pass.
- Gameplay control and full-gate receipts are recorded before merge.
