## Scope and result

Every entry from the original 318/463 name census is classified with its
C file/line, repository implementation or boundary references, and evidence:
69 plumbing, 41 merged mappings, 16 legitimate boundaries/unsupported modes,
19 gap functions. The current name census is 321/463 with 142 unnamed; all
142 are included in the original 145-row table.

Two previously unnamed helpers were restored (B63 can_play_spell, B50
consume). A third now matches the suffix scanner because of a randomPower
hook; that is still a gap, not a predicate implementation. The existing
valueKnown helper is another false positive outside this original list.
Name coverage never establishes whole-port fidelity.

Gap tasks are #4 (swaps), #75 (genocide-family defenses), #79 (home
combination optimizer), #80 (Morgoth defenses) and #81 (item analysis).
The new issues cite C/port evidence and concrete scenario requirements;
their future bug fixes own scenario tests, measurements and upstream
offers. This classification does not mark those implementations complete.

The audit checks actual declared APIs before accepting old excuses:
canonical monster/ego/object-property metadata is composed content,
unknownRunes is present but discarded, and engine stack value differs
from the C Borg's unit-style value. Curse numeric powers and global
unique-death history, by contrast, are absent from the declared views.
Optional dynamic-formula/lunal/full-munchkin modes are explicitly outside
the supported stock policy, with no enabled-mode fidelity claim.
