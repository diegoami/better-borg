# B02 The bake-off runner: the measurement instrument

- **Kind**: infrastructure
- **Issue**: #3 · **Branch**: `task/B02-bakeoff-runner` · **Merge after**: B01
- **Owns**: `tools/sweep.mjs` (or `tools/sweep/`), the reusable session
  machinery extracted from `src/play.test.ts`, `docs/runs/README.md` (schema
  additions), a run record for its own verification session.
- **Scope**: A `tools/` runner that turns the play harness into a repeatable
  instrument: boot the engine headless, drive the stock Borg over a fixed
  seed cohort, N lives per seed optional, and write a complete session record
  (`runs.json` per docs/runs/README.md: per-run command census, maxDepth,
  clvl, turns, deaths and causes, places covered) plus a summary table the
  curated README can be written from. The harness session code in
  `src/play.test.ts` is currently test-bound: extract what boots the game and
  drives the loop into a shared module the test AND the runner both call
  (write-back contract on the test file; its assertions stay). Determinism:
  seeds fixed; the runner adds no RNG of its own; wall-clock durations may be
  recorded as metadata but never influence a result. Later (Phase 2) the same
  runner becomes the fitness evaluator: keep its per-run output complete
  enough that a fitness column can be computed without re-running. A
  `--seeds`/`--lives`/`--label`/`--out` CLI is enough; no config files.
  Out of scope: parameter sweeps (Phase 2), any behavior change, any engine
  patching (published pin only - patched-engine confirmation sweeps are
  labelled separately, B01's precedent).
- **Done when**:
  1. `node tools/sweep.mjs --label b02-verify --seeds 1,7,42 --lives 1` writes
     `docs/runs/<date>-b02-verify/` with a schema-valid runs.json (asserted
     by a unit test over the writer, not eyeballed), and the sweep's seed-1
     entry reproduces the recorded door-close census (771) on the published
     pin - the instrument must see the defect B01 recorded.
  2. `src/play.test.ts` still passes byte-for-byte its current assertions
     after the extraction (the suite is the proof nothing moved).
  3. `pnpm verify` green except the recorded door-close failure (the engine
     gap, #13 - the runner does not make it disappear from the suite).
- **Hazards**: the runner quietly diverging from the test harness (two
  half-copies of the session loop) - extract ONE module, two callers; and
  recording derived numbers (averages) in runs.json instead of raw per-run
  facts - summaries are computed by the reader, stored separately.
