# B46 CI runs the play harness: the content pack from the published package

- **Kind**: defect (ours) - CI's `pnpm verify` passed with 23 tests skipped,
  the whole play harness among them, because `packRoot()` knew only
  `NEO_ANGBAND_REPO` and a sibling checkout, and CI has neither. The CI
  header (inherited from upstream) said the content package had replaced the
  checkout; this repository had never taken the dependency.
- **Issue**: #46 · **Branch**: `task/B46-ci-play-harness` · **Merge after**:
  b278f68
- **Owns**: `packRoot()`/`packSource()` in `src/play-session.ts`, the two test
  copies of `packRoot` (now imports), the runners' content lookup
  (`tools/runs.mjs`, `tools/replay.mjs`, `tools/sweep.mjs`), the CI guard in
  `src/play.test.ts`, and the docs that named the old lookup.

## Done-whens, as built

1. **`@rpgm-tools/neo-angband-content` 1.23.0-beta.1 is a devDependency**, the
   engine pin's own version. Its `pack/` is byte-identical to the sibling
   checkout's (`diff -rq`, lab branch `8b1169799`).
2. **`packRoot()` order: `NEO_ANGBAND_REPO`, the package, the sibling.**
   CHOICE: the issue said to put the package after the sibling. It goes before
   it, because the sibling is the lab branch, which moves, while the package
   is pinned and lockfile-locked like the engine. Today they are identical, so
   no number changes.
3. **Records name the pack's source.** `packSource(dir)` returns
   `@rpgm-tools/neo-angband-content <version>` for a directory under
   `node_modules`, otherwise `neo-angband@<sha>` from the checkout. It decides
   by the `node_modules` path, not the package name: the checkout's
   `packages/content/package.json` has the same name, at version beta.2. A
   name check mislabelled the checkout; the probe caught it before commit.
   runs, replay and sweep (sweep keeps its mirror copy, because its bundle runs
   from a temp dir) all write it.
4. **A skip in CI is a red.** With `CI` set (GitHub sets it), a new
   `finds the content pack in CI` test fails on a missing pack. The
   engine-readiness test also fails there on an engine that cannot play.
   Locally both still skip out loud.
5. **The two duplicate `packRoot` copies** (`rest-and-store-verification.test.ts`,
   `class/warrior/plan.test.ts`) now import the shared one.
6. **Found on the way:** `tools/replay.mjs` had its own engine-pin function
   that named the bare published version, without the carried patches. It
   now uses `tools/engine-pin.mjs`, like the other two runners (#40's intent).
