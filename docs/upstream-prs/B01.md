# B01 — upstream PR draft: `square_set_feat`'s live path never notes the changed grid (player memory goes stale; headless agents freeze)

**Target repository: `neostryder/neo-angband` (the ENGINE).** This defect is
NOT in `neostryder/neo-angband-mod-borg` — the Borg mod at pin `1fa2f8d`
reproduces it bit-for-bit and ports the relevant C faithfully. The draft below
is prepared here (task B01, issue #2), to be offered to the engine repository;
nothing is sent from this task. Run record: `docs/runs/2026-11-02-door-close/`.

---

## Title

`Chunk.setFeat` live path: call `noteSpot` on the changed grid — upstream
`square_set_feat` ends with `square_note_spot` (cave-square.c:1261), and
dropping it freezes any headless agent that reads remembered terrain

## Summary

Upstream Angband 4.2.6's `square_set_feat` has a live-play branch:

```c
/* cave-square.c:1256-1262 */
if (character_dungeon) {
    /* Remove traps if necessary */
    if (!square_player_trap_allowed(c, grid))
        square_destroy_trap(c, grid);

    square_note_spot(c, grid);   /* memorize the changed grid */
    square_light_spot(c, grid);  /* presentation */
}
```

This port wires only the trap half: `Chunk.onFeatSet` is installed by
`installChunkFeatHook` (`src/game/trap.ts:203-217`, its comment citing
"cave-square.c:1256-1259") and runs `squareSetFeatTrapSideEffect` alone. The
`square_note_spot` arm was dropped, and `square_light_spot` is presentation
(the ratified redraw divergence). Two more upstream sites reinforce the same
invariant on the close path specifically, and neither is ported either:

- `do_cmd_close_aux` (`cmd-cave.c:393-398`): after `square_close_door`, it
  calls `square_memorize(cave, grid)` and sets `PU_UPDATE_VIEW | PU_MONSTERS`
  (a closed door blocks torch light — the view itself changes). The engine's
  `closeAux` (`src/game/cave-cmd.ts:390`) only calls `setFeat`.
- `do_cmd_close_test` (`cmd-cave.c:337-341`): the REFUSAL path ("You see
  nothing there to close.") forgets a remembered-open door that is not there,
  so the player's map self-repairs. The engine's `close` handler refuses with
  the same message and returns 0 energy without the forget; the forget that
  exists sits in `closeAux`'s duplicate legality check, unreachable from the
  handler's early-out.

**Consequence.** After any live terrain change through `setFeat` (close, open,
tunnel, …), the player's known map keeps the previous terrain while the live
chunk has the new one. The web front end masks this by re-running the whole
`updateView` + `noteSpots` pass after every state-changing action (the comment
at `src/game/known.ts:306-310` documents that arrangement). The headless
harness (`runGameLoop`) has no such pass, so anything reading the frozen
AgentView — every mod autoplayer, including the Borg — reads stale terrain.

**The freeze, measured.** The Borg mod's play harness (seed 1, 1500
decisions) issues `close` at an open, seen, adjacent door; the engine closes
it; the player's `knownFeat` stays OPEN forever; the Borg — faithfully reading
remembered terrain — closes again; the engine refuses with "You see nothing
there to close." at zero energy; no turn passes; a walk never happens; and a
walk is the only remaining path that refreshes memory (`player-turn.ts:685`).
771 of 1500 decisions are spent in that loop and the game clock is frozen at
turn 8691 for 770 consecutive decisions. Evidence and probe logs:
`docs/runs/2026-11-02-door-close/` (the mod's repository).

## The fix (minimal, exactly upstream)

In the hook `installChunkFeatHook` installs, after the trap side effect:

```ts
state.chunk.onFeatSet = (grid) => {
    squareSetFeatTrapSideEffect(state, grid);
    noteSpot(state, grid); // square_set_feat's square_note_spot (cave-square.c:1261)
};
```

`noteSpot` (`src/game/known.ts`) is this engine's own port of
`square_note_spot`, guarded exactly as upstream (`squareIsSeen` or the
player's own grid), so generation-time `setFeat` calls are unaffected (the
hook is only installed on live chunks) and unseen grids are untouched.

Hardening worth considering alongside (also upstream, same invariant):
`closeAux` could mirror `do_cmd_close_aux`'s `square_memorize` + view update,
and the `close` handler's refusal path could forget a stale remembered-open
door as `do_cmd_close_test` does. The one-line `noteSpot` hook covers every
`setFeat` caller at once and is sufficient on its own.

## Proof

Same mod bytes, same content pack, only the engine differs:

| | pristine 1.23.0-beta.1 | + `noteSpot` line |
| --- | --- | --- |
| Borg play harness (`src/play.test.ts` in the mod) | 5/6; seed 1 fails: `close` 771/1500, turns frozen | **6/6 green, cap untouched** |
| seed-1 census | close 771, walk 659 | close 0, walk 1026, plus rest/pickup/tunnel/wield |
| 5-seed × 1500 sweep | seed 1 frozen; others unchanged | no seed loses depth; seed 1 reaches its deepest depth; close 0 everywhere |

Reverting the line restores the failure with the identical count 771
(bit-for-bit), which is also the reproducing test: the mod's
`keeps playing for 1500 decisions (seed 1)` assertion fails without the fix
and passes with it. An engine-side regression test could pin the invariant
directly: start a game, place a seen open door, close it, and assert the known
map (`knownFeat`) reports the door closed before any further command.
