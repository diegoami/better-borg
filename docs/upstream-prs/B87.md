# Prepared C bug report: west-side light coverage

Internal review and posting gate: [Mandos #89](https://github.com/diegoami/mandos/issues/89).
No upstream issue or PR has been posted. The [real C validation report](../audit/c-reports/B87/README.md)
and [carry patch](../../patches/upstream-c/B87-west-light.patch) support this proposal.

## Proposed title

Borg: radius-two light misses the two west shoulder grids

## Proposed issue text

In `src/borg/borg-cave-light.c`, `borg_update_light()` marks the west corners twice instead of marking the west shoulders. Verified against official C master `e473720ed88a0f0c7ca66815cef3000eb4a38bc3`.

The east arm uses y offsets +/-1 at x+2, while the west arm uses +/-2 at x-2. The corner grids are already added by the north/south arms. The missing west shoulder flags also persist at larger light radii because the later scan skips the central five-by-five box.

Reproduced in a built C Angband engine with the C Borg using a deterministic headless frontend, not an extracted function or manufactured map. Seed 1000, Human Warrior, turn 71, town depth 0, Borg position (32,8), light radius 2: all four floor gates naturally hold. The unchanged C Borg has west shoulder bits 0/0, east 1/1, and 21 light-list entries covering 19 distinct grids. Changing only the two west y offsets from +/-2 to +/-1 gives west 1/1, east 1/1, and 21 distinct grids at the same turn and position.

The observer is guarded by BORG_HARNESS and does not change game/Borg state or draw RNG. Its baseline key log is byte-identical to the unobserved C run and the pinned C reference (180210 bytes; SHA256 06885c7e77e46d5c70eba6b16f2d7fd900cd13824361bfe13d784d9d4ddae51a). C code was compiled and linked; no Rust Borg library is present.

This is a defect in the Borg's perceived-light cache, not a claim that the game's lighting engine is broken, and no specific death is attributed to it. Both before/after 100,000-turn runs survive at clevel 7/maxdepth 3, with different later paths; no strength gain is claimed.
