Mandos is a bug-fix consumer, not an experimental platform. Read
[the scope contract](docs/MANDOS-SCOPE.md) and scope181 before selecting work.
This session owns its own defects, applicable verified source correction
adoption/C-to-TS translation, targeted regressions and basic run/death/stall
records. Strategy research, broad cohorts, stage/save ladders and advanced
analysis/trainer/export work are parked; preserve their code/evidence/branches.
Prefer the unpatched published engine. A carry requires a demonstrated necessary
Mandos gameplay fix and removal condition; optional replay/PR433 is not a default
runtime or upgrade prerequisite. Runtime180's actual proof selects the profile.
It does not implement upstream Neo Borg, Neo engine or native C repairs.

Port defects and their fix branches live in diegoami/neo-angband-borg-mod-tracker
(`../neo-angband-borg-mod-tracker`). C Borg, Angband game and Neo engine defects
live in diegoami/neo-angband-tracker (`../neo-angband-tracker`). Link the canonical
owner issue and keep Mandos integration tasks distinct, with named package/plugin/lab consumer receipts.
Transferred historical issue URLs redirect; use qualified canonical refs for
new text. docs/migrations/repository-split.json is the transfer map.

The two fork workspaces have their own AGENTS/RULES/PLAN/checkpoint. The
umbrella owns orchestration, scoped dispatch, dependency handoffs and recovery
metadata; component sessions retain code/issue ownership. Preserve the existing live lab and
pristine reference checkouts; never silently switch their branches/data.
Broad upstream reconciliation is a weekly manual batch or explicit owner task;
use targeted checks for active blockers, source applicability and closure.
Do not proactively poll/fetch borg-rs: it reports directly to our engine/C board.
Read the current bug and relevant source/action comments, including edits.
The advanced death-session contract in docs/deaths/DISCUSSIONS.md is preserved
optional reference, not a routine task or default-upgrade gate. ACK is not
resolution; no unattended monitoring is implied. Future experiments need their
own authorized better-borg-c/borg-rs session; no automatic code/task migration. See docs/process.md for the gate and adoption loop.
